  - **A vs B:** **A** — в PATH одна команда `ng`, удобно часто вызывать `ng new` / `ng serve`; минусы: возможны **`EACCES`** при неправильном префиксе глобального npm и рассинхрон версии **глобального** `ng` с версией CLI **внутри** уже созданного проекта. **B** — не ставит пакет глобально, меньше проблем с правами и «корпоративным» npm; минусы: длиннее команды (`npx @angular/cli@latest …`), при первом запуске возможна загрузка. Версию в **B** можно зафиксировать явно (`@angular/cli@20` и т.д.), чтобы совпадала с документацией.
  - **Что выбрать:** для старта в Taskflow разумно **B**; **A** — если вы уже настроили глобальный каталог npm (без `sudo`) и хотите привычное короткое `ng` во всех папках.
  - [x] ✅ **Команда (вариант A):** `npm install -g @angular/cli` — N/A для текущего проекта (осознанно выбран вариант B без глобальной установки)
    - **Что делает:** ставит CLI в глобальный `node_modules`, появляется команда `ng` в PATH.
    - **Где:** терминал; на macOS/Linux иногда нужны права или настройка каталога для глобальных пакетов.
    - **Успех:** `ng version` находит команду; в выводе — таблица версий Angular.
    - **Частая ошибка:** `EACCES` — не использовать `sudo` для npm без необходимости; лучше вариант B или исправить права на каталог npm.
  - [x] ✅ **Команда (вариант B):** `npx -y @angular/cli@latest version`
    - **Что делает:** одноразово скачивает/кэширует CLI и запускает `ng version` без глобальной установки.
    - **Где:** любая директория; для `ng new` ниже можно каждый раз вызывать через `npx @angular/cli@latest …`.
    - **Успех:** тот же осмысленный вывод версий, что и у глобального `ng version`.
